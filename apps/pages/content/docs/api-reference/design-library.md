# Search the design library

API and MCP access are free. Create an account and generate an API key in
[Account settings](/settings). No subscription is required.


Use your [personal API key](/docs/api-reference/introduction/) to read published, ready-to-view designs.

```bash
curl 'https://tastefulkit.com/api/v1/designs?q=warm%20minimal&kind=landing_page' \
  -H "Authorization: Bearer $TASTEFULKIT_API_KEY"
```

## Filter and paginate

All query parameters are optional:

| Parameter | Use |
| --- | --- |
| `q` | A text description, such as `warm minimal`. |
| `kind` | Use `landing_page` for the landing-page catalog. |
| `tag` | A style tag from the library. |
| `industry` | An industry from the library. |
| `page` | A page number, starting at `1`. |

Filters combine, just as they do in Explore. URL-encode spaces and other special characters in parameter values.

The response contains `items`, `page`, `pages`, `total`, and `search_mode`. Each page contains up to 24 designs. Use `pages` to decide whether to request another page. An empty search returns an empty `items` list.

Each design includes its ID, title, description, source URL, tags, and screenshot links. Keep the ID if you want to fetch the same example again.

## Fetch one design

Replace `DESIGN_ID` with an ID returned by search:

```bash
curl 'https://tastefulkit.com/api/v1/designs/DESIGN_ID' \
  -H "Authorization: Bearer $TASTEFULKIT_API_KEY"
```

The detail response also includes `design_markdown`: the complete, portable DESIGN.md text, or `null` for an older reference that has not been backfilled. List/search results omit this large field.

Screenshot links expire after 15 minutes. Fetch the design again for fresh links instead of storing an image URL as a permanent reference.

## Handle errors

- **401:** Check your API key and request header.
- **404:** The design does not exist or is not available to your account.
- **422:** Check parameter types, including the page number or design ID.

Ordinary accounts only see published designs with ready screenshots. This read API does not manage your Saved list; use the website to save or remove references. The [interactive schema](/api/docs) provides the complete request details.

## Submit a prepared example (administrators)

Prepare the complete example outside TastefulKit. The application does not visit
source pages, capture screenshots, create thumbnails, write design guidance, or
generate catalogue embeddings. It validates and stores your supplied files and
indexes your supplied vector before returning success.

Only API keys belonging to active **superusers** can submit. Staff status alone is
not enough. MCP is read-only; use this POST endpoint for all creation and refreshes.

Send `multipart/form-data` with four fields:

| Field | Contents |
| --- | --- |
| `payload` | A JSON object matching the fields below. |
| `screenshot` | A prepared static PNG, JPEG or WebP, up to 20 MiB and 40 million pixels. Full-page image width must match `viewport_width`; selector captures may be narrower. |
| `thumbnail` | A separately prepared static image in the same supported formats, up to 2 MiB and 1440 × 1440 pixels. |
| `design_md` | The example-specific UTF-8 DESIGN.md, up to 128 KiB. |

The JSON `payload` requires `title`, `source_url`, `description`, `captured_at`
(an ISO timestamp with timezone), `embedding_model`, and `embedding`. Optional
fields are `kind` (default `landing_page`), `tags`, `industry`, `selector`,
`viewport_width` (default 1440), and `replace_existing` (default false).
Unknown fields are rejected. See the [interactive schema](/api/docs) for limits.

Prepare a finite, nonzero **768-dimensional** embedding using
`@cf/baai/bge-base-en-v1.5`, and set `embedding_model` to that exact name.
Use the title, kind, industry, description and tags as the embedding input.
A different model's vector is not interchangeable even if it has 768 values.
Query embeddings are still generated at search time; no example embeddings are
generated by the application.

DESIGN.md should follow the [pinned upstream alpha format](https://github.com/google-labs-code/design.md/blob/9bf8eae67128b6cc55ad9bf86665767deb4c11cd/docs/spec.md).
Include a YAML design name, color and typography tokens, and actionable Markdown
sections describing the individual reference. Record palette, typography, layout,
spacing, responsive behavior, components, and practical do's/don'ts where observed.
Label estimates and unavailable details. The file must work in another repository
without TastefulKit internals.

Before submission, run the upstream linter in your preparation environment and
review its warnings and the file's visual fidelity. The API performs bounded
structural validation (UTF-8, YAML, required token groups, Markdown sections, and
non-circular/resolvable references), not a substitute for the upstream linter or
human/agent review. YAML aliases and duplicate keys are not accepted. Files are
stored without rewriting their content.

Save the complete metadata and real embedding in `payload.json`, then upload:

```bash
curl --fail-with-body 'https://tastefulkit.com/api/v1/designs' \
  -H "Authorization: Bearer $TASTEFULKIT_ADMIN_API_KEY" \
  -F 'payload=<payload.json' \
  -F 'screenshot=@screenshot.png;type=image/png' \
  -F 'thumbnail=@thumbnail.png;type=image/png' \
  -F 'design_md=@DESIGN.md;type=text/markdown'
```

Do not set a JSON Content-Type header: the client supplies the multipart boundary.
Images are uploaded as bytes, never fetched from a caller-supplied asset URL.
Source URLs must be public HTTP(S) URLs without credentials or nonstandard ports.

A new design returns **201** and is ready and published immediately, with no polling
or worker step. URL + kind + selector + viewport width identify the example.
An existing identity returns **200** unchanged by default. To refresh or backfill
that same example, explicitly set `replace_existing: true` and resend the entire
bundle. Its ID, saved-design links, submitter, and current moderation visibility
are preserved; changing an identity field instead creates a different example.

**422** means the bundle is incomplete or invalid. **503** means storage/indexing
failed: retry the complete request, never assume it published. A timeout may occur
after acceptance; resend normally and compare the returned ID/content. There is
no background retry or enrichment, and the old `/retry` endpoint is retired.

Older examples remain usable while an agent prepares their missing files. Backfill
through the same explicit replacement POST; the application does not generate
DESIGN.md for them automatically.
